# go-integration-test-patterns

Сравнение подходов к интеграционным тестам на Go с настоящей PostgreSQL: как изолировать данные
и можно ли запускать тесты параллельно.

Предмет — учебная пекарня (`internal/bakery`):
- `Repository` — заказы выпечки;
- `Oven` — фоновый воркер, который за проход печёт **все** заказы в очереди (как типичный воркер,
  сканирующий таблицу). У духовки есть время выпекания — оно имитирует ожидание сети и внешних систем,
  на которое уходит основное время интеграционных тестов.

Во всех подходах проверяются одни и те же сценарии.

## Подходы

| # | Каталог | Изоляция | Параллельность |
|---|---|---|---|
| 1 | `tests/01_shared_db` | одна БД, `TRUNCATE` перед каждым тестом | только `-p=1` |
| 2 | `tests/02_db_per_package` | своя БД из шаблона на каждый пакет | пакеты параллельно |
| 3 | `tests/03_unique_data` | одна БД, у каждого теста свои данные | `t.Parallel()` внутри пакета |
| 4 | `tests/04_tx_rollback` | транзакция на тест, в конце `ROLLBACK` | `t.Parallel()`, но с ограничениями |
| 5 | `tests/05_testo` | подход 3 на фреймворке Testo | плагин параллельности |

## Запуск

```bash
docker compose up -d --wait
go test -tags=integration -p=1 -count=1 ./tests/01_shared_db/...
```

Адрес БД — переменная `TEST_DATABASE_URL`, по умолчанию Postgres из `docker-compose.yml` (порт 5433).

## Результаты

### Подход 1 — общая БД

- `-p=1`: стабильно зелёный.
- `-p=2`, 5 прогонов: один прогон упал — `TRUNCATE` одного пакета стёр данные посреди теста другого,
  глобальные проверки (`CountByStatus`, «духовка взяла ровно один заказ») не сошлись.
- При `-p=2` пакет без воркера стал медленнее (0,8 с → 2,5 с): `TRUNCATE` берёт эксклюзивную блокировку
  таблицы и ждёт соседние транзакции.

### Подход 2 — своя БД на пакет

`internal/testdb/database.go`: один раз создаётся `bakery_template` с миграциями (под advisory-блокировкой,
чтобы параллельные пакеты не создавали его дважды), каждый пакет делает `CREATE DATABASE … TEMPLATE`
и в конце `DROP DATABASE … WITH (FORCE)`. Сами тесты не изменились — поменялась одна строка в `SetupSuite`.

- `-p=2`, 5 прогонов: 5 из 5 зелёные.
- Время всего набора: `-p=1` — 12,1 с, `-p=2` — 7,9 с.
- Тестовые БД после прогона удаляются.
- Ограничение: тесты, которые ходят в отдельно поднятый сервис (HTTP, консьюмер в другом процессе),
  так не изолировать — сервис смотрит в свою БД, а не в базу пакета.
