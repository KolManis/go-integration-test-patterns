# Другие общие ресурсы

Изолировать Postgres мало: параллельные тесты конфликтуют на **любом** общем ресурсе.

| Ресурс | Проблема | Что делать |
|---|---|---|
| ClickHouse | Общий DSN, глобальный `TRUNCATE` гонится с соседями | Своя БД (`CREATE DATABASE test_<id>`) на пакет; или таблицу чистит только её единственный потребитель; или уникальные данные |
| S3 / файлы | Один бакет / каталог | Префикс ключа на тест; `t.TempDir()` для локальных файлов |
| Порты | Два пакета поднимают HTTP-сервер на одном порту | Порт `:0` (выдаёт ОС), `httptest.NewServer` |
| Переменные окружения | `os.Setenv` действует на весь процесс | `t.Setenv` (запрещает `t.Parallel` в этом тесте — и правильно) |
| Время | Тесты двигают «текущее время» глобально | Передавать часы зависимостью (`Clock`), не глобальная переменная |
| Глобальные переменные / синглтоны | Пакетные `var` меняются тестами | Не трогать в параллельных тестах или выносить в зависимость |
| Внешние HTTP-сервисы (WireMock и т. п.) | Общие стабы: тест A перезаписывает стаб теста B | Стабы с уникальным параметром запроса; свой экземпляр мока на пакет; сброс только своих стабов |
| Feature-флаги | Тест переключает флаг для всех | Флаг передавать конфигом в тестируемый объект, а не через общий сервис флагов |
| Счётчики/sequence | `RESTART IDENTITY` и ожидание `id = 1` | Не полагаться на конкретные id |
