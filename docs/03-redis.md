# Redis

## Проблема
Общий Redis + `FLUSHALL` после теста = тот же `TRUNCATE` в общей БД: один пакет стирает ключи другого.

## Способы

### Номер БД на пакет (процесс)
Redis в одном экземпляре держит несколько логических БД (по умолчанию 16: `0–15`). Адрес `redis://host:6379/<N>`.
- После теста `FLUSHDB` (чистит только свою БД), а не `FLUSHALL`.
- ✅ Код приложения не меняется — меняется только адрес.
- ❌ Баз ограниченное число. Больше — через `databases 64` в `redis.conf`.
- ❌ Нужна проверка «процессов не больше, чем баз», иначе при большом `-p` процессы попадут в одну БД.
- ❌ Не работает в Redis Cluster (там только БД 0).
- Как выдать номер в Go: пакетов больше, чем баз, поэтому номер берут не по пакету, а по «слоту» — например, под advisory-блокировкой в Postgres или через атомарный `INCR` в Redis по модулю числа баз с ожиданием свободного.

### Префикс ключей
Все ключи пишутся как `<testID>:<key>`, очистка — `SCAN` по префиксу + `DEL`.
- ✅ Нет лимита на число процессов, работает в кластере.
- ❌ Нужна обёртка над клиентом или опция префикса в коде приложения.

### Свой контейнер Redis
testcontainers на пакет. Максимальная изоляция, дольше старт.

### Уникальные ключи
Как уникальные данные в Postgres: тест использует ключи со своим id и не чистит ничего глобально.
