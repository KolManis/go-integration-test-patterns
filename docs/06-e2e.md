# Тесты на поднятый сервис (e2e / функциональные)

Тест ходит в сервис по HTTP/gRPC, сервис работает со своей одной БД, своими консьюмерами и воркерами.

## Что не работает
- **БД на пакет** — сервис смотрит в свою БД, а не в базу пакета.
- **Транзакция с откатом** — сервис не видит незакоммиченные данные теста.
- **`TRUNCATE` из теста** — стирает данные всех тестов и мешает самому сервису.

## Что работает
- **Уникальные данные.** Каждый тест создаёт своих сущностей с уникальными id и проверяет только их.
- **Фильтр по своему id** при чтении из Kafka / outbox / логов.
- **Ожидание по условию** («статус моей записи стал done за ≤ 10 с») вместо `sleep`.
- **Отдельный сервис на прогон** (своя БД, свои топики) — если инфраструктура позволяет поднимать окружение на каждую ветку.

## Что переписывать в таких тестах
- убрать глобальные подсчёты и проверки «пусто»;
- фоновые воркеры обрабатывают всю таблицу — проверять результат по своим записям;
- не полагаться на порядок и номера id;
- стабы внешних сервисов делать уникальными для теста.

Это дороже, чем БД на пакет, поэтому переводить тесты по одному, начиная с самых долгих.
