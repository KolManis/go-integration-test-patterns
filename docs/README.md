## Главная мысль в одной таблице

| Ситуация | Что выбрать |
|---|---|
| Много легаси-тестов с `TRUNCATE`, код ходит в БД напрямую | **БД на пакет (процесс)** из шаблона. Тесты почти не меняются |
| Новые тесты, хочется параллельности внутри пакета | **Уникальные данные** + `t.Parallel()` |
| Тестируем только репозитории, код не коммитит сам | **Транзакция с откатом** — самый быстрый вариант |
| Тесты ходят в отдельно поднятый сервис | Только **уникальные данные**: сервис видит одну свою БД |
| Хочется сьютов, хуков, параметризации | Фреймворк (Testo и т. п.) — **поверх** одного из способов выше, изоляцию он не даёт |

Правило: сначала изоляция данных, потом параллельность. Параллельность без изоляции даёт нестабильные тесты.
