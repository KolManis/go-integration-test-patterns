# Kafka

## Сначала проверить: есть ли брокер в тестах вообще
Часто интеграционные тесты Kafka не используют:
- консьюмер тестируют вызовом обработчика напрямую: `consumer.Handler(ctx, msg)`;
- продюсер пишет событие в outbox-таблицу (transactional outbox), а не в брокер.

Тогда Kafka **не мешает** параллельности: outbox лежит в Postgres, и при БД на пакет у каждого пакета свой outbox. Проверить просто — поднимается ли Kafka в CI-джобе (`services`).

## Где Kafka мешает: тесты с настоящим брокером
1. **Чужие сообщения в топике.** Тест ждёт «пришло событие» и ловит событие соседа → ложный успех или падение.
2. **Общая consumer group у тестовых читателей.** Kafka делит партиции между участниками группы — каждый видит только часть сообщений.
3. **Проверки «ничего не пришло» / «пришло ровно N»** на общем топике ненадёжны.
4. **Тест не дождался обработки** своего сообщения и закончился — его сообщение обработается во время следующего теста.

## Способы

| Способ | Как | Когда |
|---|---|---|
| Свой id и фильтр | В сообщение (тело или заголовок) кладём уникальный id теста, читатель принимает только свои | Общий брокер, общий сервис — основной вариант |
| Своя consumer group на тестового читателя | `test-<uuid>`, чтение с конца топика, подписка **до** отправки | Всегда при чтении в тестах |
| Свой топик / префикс на прогон | `orders-<runID>`, топики создаются явно | Если сервис поднимается на прогон со своими именами топиков |
| Свой брокер на пакет | testcontainers (Kafka/Redpanda) | Интеграционные тесты с настоящим брокером, максимум изоляции |
| Ждать по условию с дедлайном | «дождаться своего сообщения ≤ 10 с», не `sleep` | Везде |
| Метка изоляции в сообщении (routing key) | Метка идёт с каждым сообщением, консьюмеры фильтруют | Общие стенды на много веток (подход Signadot) |

## Памятка для теста с брокером
- уникальный id в каждом сообщении;
- уникальная consumer group у читателя, подписка до отправки;
- ожидание по условию с таймаутом;
- проверять только свои сообщения;
- закрыть консьюмера в `t.Cleanup`;
- для проверки ребалансировки нужен топик с несколькими партициями.
